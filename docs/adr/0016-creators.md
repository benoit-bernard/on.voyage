# ADR-0016 — Service Creators, créateurs fondateurs et file de modération simple (T-1201, T-1202)

- Statut : accepté — MVP-0. Hors périmètre : comptes connectés et import (F-27, T-1207/1208), géo-association IA (F-28, T-1209), listes et itinéraires (F-29, `CreatorListChangedV1`, T-1210), « Voyage comme » (T-1211), statistiques (F-32, `creator_stats_daily`, T-1212), modération complète avec notification et contestation (T-1213), espace `Web.Studio` (T-1206), app et web public (T-1203, T-1204), projections de Discovery (T-1205).

## Service Creators (`src/Services/Creators`)
- Domain / Application / Contracts / Infrastructure / Api, schéma `creators`, une migration `Initial`. Tables : `creator`, `content_item`, `place_link`, `creator_tip`, `follow`, `poi_directory`, `moderation_case` (voir `docs/DATABASE.md`). `handle` est un `citext` à index unique : l'unicité ignore la casse, et la base elle-même refuse un doublon (test).
- **Règle de publication (F-26)** dans le domaine (`Creator.PublishBlock`) : refus `terms_required` tant que ni les CGU créateurs ni le consentement fondateur ne sont enregistrés (`terms_version = fondateur` **et** référence du document, sinon le consentement ne compte pas), puis `specialty_required` (au moins une spécialité de la taxonomie, 5 au plus). Un profil publié ne peut pas perdre sa dernière spécialité. Publier depuis « suspendu » lève la suspension.
- **Lectures publiques** : une seule requête de visibilité (`CreatorQueries.Visible`) sert la page, la liste et le bloc d'un lieu : lien `validated`, créateur `published`, lieu `is_published` du répertoire, contenu `imported` (ou sans contenu). Tests : chaque condition retirée fait disparaître le créateur des trois lectures. Abonnés : `null` sous 20 (« Nouveau créateur »). Aucune route n'accepte une position.
- **Contenus par URL (D-17)** : `ContentUrls` reconnaît YouTube (`watch`, `youtu.be`, `shorts`), Instagram (`p`, `reel`, `tv`) et TikTok, en https, et garde le lien canonique. Un chapitre donne un lien `&t=Ns` (YouTube). Aucun média n'est copié. Unicité (`platform`, `external_id`).
- **Unité de travail** : les dépôts préparent les changements, `CreatorsUnitOfWork` les enregistre avec les événements dans la même transaction (outbox Wolverine, `IDbContextOutbox`). L'entrée du journal d'audit (`AdminActionRecordedV1`, vers la file `platform`) est dans cette transaction : une écriture admin sans trace est impossible. Une violation d'index unique devient `UniqueConflictException` (handle, compte, contenu pris entre-temps).
- **Événements** : `CreatorPublishedV1` (aussi à chaque modification d'un profil publié : handle, nom, avatar, spécialités), `CreatorUnpublishedV1` (motif), `CreatorPlaceLinkChangedV1` (`validated` / `removed`, seulement quand l'ensemble publié change ; un contenu masqué, retiré ou dont le drapeau publicité change réémet ses liens validés), `CreatorTermsAcceptedV1`, `FollowChangedV1` (au premier changement seulement), `AdminActionRecordedV1`. `CreatorTermsAcceptedV1` part quand le consentement **et** un compte sont là, dans l'ordre où ils arrivent, et à chaque nouvel enregistrement.
- **Routage** : Platform reçoit toujours `CreatorTermsAcceptedV1`, `AdminActionRecordedV1`, `TravelerDataDeletedV1` et `TravelerExportPartReadyV1` (file `platform`). Les quatre événements pour Discovery / Insights vont aux files listées dans `Messaging:CreatorSubscribers`, **`["discovery"]` par défaut depuis T-1205** (ADR-0018) ; `insights` s'ajoutera avec ses gestionnaires (T-1212), un message sans gestionnaire serait mis de côté.
- **Consentement et rôle** : l'administrateur enregistre le consentement écrit (`PUT …/consent`, référence du document) puis rattache le compte (`PUT …/account`, un compte pour un créateur). Platform ajoute `creator` à `roles` à la réception de `CreatorTermsAcceptedV1` (`CreatorTermsAcceptedHandler`) : jamais à un compte anonyme ni inconnu (journalisé), une seule fois. Le rôle figure dans les jetons suivants.
- **Associations et conseils saisis par l'administrateur** : une association ajoutée par l'administrateur est `validated` d'emblée (il agit avec le consentement du créateur ; la validation par le créateur est celle du Studio, T-1206/1209) ; `proposed` et `rejected` restent possibles. Un conseil sur un lieu où le créateur n'a aucune association crée l'association « conseil seul » (`content_id` nul), pour que le conseil puisse s'afficher.
- **Réclamation de handle (F-33)** : `POST …/handle-claim` : le créateur du chemin prend le handle, son détenteur est dépublié (`CreatorUnpublishedV1` « handle_claimed »), renommé avec la première variante libre, dans une seule transaction (deux écritures ordonnées pour l'index unique). Le créateur publié est annoncé de nouveau sous son nouveau handle.
- **Modération simple (F-33)** : `POST /reports` (cible `creator`, `content`, `place_link` ou `tip`, motif d'une liste fermée, **pas de texte libre**), un doublon ouvert du même voyageur renvoie le même dossier. La file n'expose jamais l'auteur. Décision `dismissed` ou `upheld` ; `upheld` exige un exposé des motifs et retire la cible (créateur suspendu, contenu masqué, association rejetée, conseil masqué) en annonçant les retraits.
- **Droits des données (ADR-0015)** : `TravelerDeletionRequestedV1` supprime les abonnements, retire la référence du voyageur des signalements (le signalement reste) et, si le voyageur est un créateur (`account_id`), son profil en cascade, après publication des retraits ; réponse `TravelerDataDeletedV1("creators")` renvoyée par le gestionnaire comme celui de Discovery. `TravelerExportRequestedV1` écrit `creators.json` dans `ExportStorage`. `Exports__Directory` est posé pour `creators-api` dans l'AppHost.
- **Gateway** : `/api/creators/v1/admin/**` (politique `admin`, ordre -1) puis `/api/creators/**` (`traveler`). Aucune route `studio` : elles viendront avec le rôle `creator` (T-1206).

## Catalog → `PoiProjectionChangedV1`
- Contrat dans `OnVoyage.Catalog.Contracts/Events` : identifiants, version, destination, slug, noms FR/EN, alias, ville, coordonnées, importance, qualité, `HiddenGem`, pic de fréquentation, poids, drapeaux, `IsPublished`. Les coordonnées servent Discovery ; **Creators les ignore** (`poi_directory` n'a aucune colonne de position).
- Après `PoiPublishedV1` ou `PoiUnpublishedV1` de Factory, le Catalog renvoie l'événement construit **à partir de son état stocké** (`IPoiProjectionWriter.ProjectionAsync`), vers les files de `Messaging:ProjectionSubscribers` (défaut `creators`, `discovery`). Une redistribution de l'événement de Factory réémet donc l'état courant : sans effet pour les consommateurs (clé = version), et un arrêt entre l'écriture et l'annonce ne la perd pas. Un lieu inconnu n'annonce rien.
- Discovery accuse réception (`PoiProjectionChangedHandler`, vide) pour que l'événement ne soit pas mis de côté ; il continue de lire les événements de Factory (ADR-0011) jusqu'à T-502.

## Écrans d'administration (`Web.Admin`)
- `/admin/creators` (liste filtrable, création d'un fondateur), `/admin/creators/{id}` (publication, profil, consentement et compte, contenus, associations et conseils, réclamation de handle), `/admin/moderation` (file, décision motivée). Liens dans le menu. Par `ICreatorsAdminApi` / `HttpCreatorsAdminApi`, séparée de `IAdminApi` (autre service derrière le Gateway) ; le transport HTTP commun est dans `GatewayCaller` et `AdminPageBase` est scindée (`AdminActionBase`) pour que ces pages n'exigent pas `IAdminApi`. Les modèles sont les DTO de `Creators.Contracts` (sans dépendance), comme `Platform.Contracts`.
- **Le bouton « Publier » est désactivé avec la raison en français** (`Labels.PublishBlock`, `aria-describedby`) tant que `publishBlock` n'est pas vide ; le service garde le dernier mot (un refus est affiché tel quel).

## Écarts au cahier
- **Tables** : `connected_account`, `creator_list`, `creator_list_item`, `creator_stats_daily` non créées (hors périmètre). `creator.account_id` n'est pas « l'id Supabase » (ADR-0005). `poi_directory` n'a pas de `location` (demande explicite) mais une colonne `name`, `destination_slug` et `search_text` (recherche trigramme sans accents). `creator_tip` a un `id` en plus de sa clé (cible d'un signalement). `place_link` : unicité (`creator_id`, `poi_id`, `content_id`, `start_s`).
- **Bloc « Vu par les créateurs »** : le vecteur `c` de chaque créateur (tri sur l'appareil, §6.15) n'est pas renvoyé : il vient de Discovery/T-1205.
- **Événements** : `CreatorListChangedV1` et `PlaceSuggestedV1` ne sont pas publiés (listes, géo-association). `CreatorPlaceLinkChangedV1.Kind` vaut `tip` pour un conseil seul. Le contenu de `CreatorUnpublishedV1.Reason` est le motif saisi ou un code (`handle_claimed`, `moderation`, `account_deleted`).
- **`PoiProjectionChangedV1`** : `not_for_kids` n'existe pas encore chez Factory/Catalog ; les drapeaux sont `fragile`, `access_regulated`, `hidden_gem`. Le Catalog n'a ni ville ni alias : la ville est le nom de la destination, les alias sont vides.
- **Modération** : la décision n'est pas notifiée au créateur et il ne peut pas la contester (T-1213) ; l'avertissement après publicité non déclarée n'existe pas ; `reporter_ref` est effacé à la suppression au lieu d'être « anonymisé » autrement.
- **Réclamation de handle** : la preuve de titularité est un motif en texte libre dans le journal ; aucune vérification automatique.
- **Liste des créateurs** : curseur = décalage, tri par nombre de lieux validés (puis handle) ; adapté aux quelques dizaines de créateurs du MVP-0, à revoir avec un tri par clé au-delà.
- **Observabilité** : traces et journaux standards (ServiceDefaults) ; pas encore de métriques métier du service.

## Non vérifié
- **Aspire de bout en bout** (AppHost, Gateway réel, plusieurs processus) : seules les paires sont testées (Creators ↔ Platform pour le rôle, Catalog → file pour la projection). Le déploiement (`deploy/`) ne contient pas `creators-api`.
- **Image `postgis/postgis:16-3.4`** : les tests ont tourné sur PostgreSQL 16 d'Ubuntu avec PostGIS 3.4 ; `citext` et `pg_trgm` y sont des extensions standard (contrib) mais la migration n'a pas été jouée sur l'image elle-même. L'unicité avec valeurs nulles égales demande PostgreSQL 15 ou plus.
- **Écrans** : bUnit et l'hôte de test (403, menu, appels au Gateway avec le jeton) ; pas de passage dans un navigateur (mise en page, clavier, lecteur d'écran).
- **Discovery** consomme les événements de Creators depuis T-1205 (ADR-0018).
- **Concurrence** : deux `PUT` de suivi simultanés du même couple peuvent faire échouer l'un des deux (clé primaire) ; il suffit de répéter. Pas de test de charge.
- Notifications par e-mail au créateur, import de la bio ou de la photo : non faits.

## Vérification
Échecs préexistants, sans rapport : trois tests de `Platform.IntegrationTests.DataRightsTests` (`Expired_exports_are_cleaned_up_with_their_files`, `An_export_gathers_platform_and_discovery_data_into_one_archive_for_24_hours`, `Asking_twice_returns_the_request_under_way_and_publishes_nothing_more`) échouent de la même façon avant ce travail (commit `70d490f`) sur cette machine : précision des dates (microsecondes de PostgreSQL), nom d'une propriété JSON de l'export de Discovery, jeton expiré par l'horloge simulée. Non corrigés ici.

Creators : 69 tests unitaires (domaine : handle, règle de publication, URL, chapitres, modération ; gestionnaires avec dépôts simulés), 50 d'intégration sur PostgreSQL (cycle de vie, règle F-26, handle insensible à la casse et suggestion, visibilité publique condition par condition, événements en file, audit, abonnements, signalements et décisions, réclamation, droits des données, projection, schéma sans position). Platform : 3 tests unitaires et 2 d'intégration (Platform + Creators) pour le rôle `creator`. Catalog : 2 tests unitaires et 3 d'intégration de `PoiProjectionChangedV1`. Gateway : routes et politiques de Creators. Web.Admin : 35 nouveaux tests (34 bUnit sur données fixes, 1 sur l'hôte de test).
